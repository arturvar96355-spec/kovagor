# Telegram-бот: заявки и переписка с клиентами

## Как это устроено
- Есть **один бот** (клиенты видят его имя) и **приватная группа менеджеров** с включёнными «Темами».
- Заявка с сайта → в группе появляется **тема «#12 Имя»** с карточкой заявки.
- После отправки формы клиенту показывается кнопка **«Продолжить в Telegram»**. Он нажимает → бот «привязывает» его чат к этой теме.
- Дальше переписка идёт **через бота**: клиент пишет боту — сообщение появляется в его теме; вы (или менеджер) отвечаете **в теме** — ответ уходит клиенту от имени бота. Отдельный аккаунт для общения с клиентами не нужен: вы пишете из своих обычных аккаунтов внутри группы.
- Клиент может написать боту и без заявки — для него создастся новая тема.
- Поддерживается всё, что умеет Telegram: текст, фото, файлы, голосовые.
- Доступ менеджеров = **членство в группе**. Добавили человека в группу — он отвечает клиентам; удалили — доступа нет.

Команды в теме: `/close` — закрыть обращение (следующее сообщение клиента откроет новую тему). Остальные «/…» клиенту не пересылаются.
Под вашим сообщением бот ставит 👍 — значит, доставлено. Если клиент заблокировал бота или ещё не открыл его, бот напишет об этом в теме (и покажет контакт из заявки).

## Настройка (один раз)
1. **Создать бота.** В Telegram откройте @BotFather → `/newbot` → имя и username (например, `kovagor_bot`). Сохраните **токен**.
   Рекомендуется: `/setprivacy` не нужен (бот будет администратором); `/setdescription` и `/setuserpic` — на ваш вкус.
2. **Создать группу.** Новая группа → добавьте себя и менеджеров → в настройках группы включите **Темы** (Topics): группа станет супергруппой. Сделайте её **приватной** (без публичной ссылки).
3. **Добавить бота в группу как администратора** с правом **«Управление темами»** (остальные права не нужны).
4. **Заполнить `.env` на сервере** (см. `.env.example`): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET` (`openssl rand -hex 24`), `DATA_DIR`.
5. **Узнать id группы.** Напишите в группе любое сообщение, затем:
   ```bash
   node --env-file=.env scripts/telegram-setup.mjs --find-group
   ```
   Скопируйте число вида `-100…` в `TELEGRAM_GROUP_ID`.
6. **Подключить вебхук** (после выкладки сайта с HTTPS):
   ```bash
   node --env-file=.env scripts/telegram-setup.mjs https://kovagor.ru
   ```
   Скрипт сам проверит: токен, username, что группа — супергруппа с темами, что у бота есть нужное право, и укажет Telegram адрес `/api/telegram`.
7. **Проверка:** отправьте заявку с сайта → в группе появится тема → нажмите «Продолжить в Telegram» → ответьте в теме.

## Если сервер в России и Telegram недоступен
Многие российские хостинги не соединяются с Telegram (проверка: `curl -m 10 -sS -o /dev/null -w "%{http_code}\n" https://api.telegram.org/` — `000` или таймаут значит «закрыто»). Тогда бот не сможет ни отправлять, ни принимать сообщения. Выход — **ретранслятор** на маленьком зарубежном сервере (Нидерланды/Финляндия/Германия, самый дешёвый тариф: Ubuntu 24.04, 1 vCPU, 1 ГБ):

```
сайт (РФ)  ──>  ретранслятор (за рубежом)  ──>  api.telegram.org
Telegram   ──>  ретранслятор                ──>  сайт (/api/telegram)
```
Данные заявок и `bot.sqlite` остаются на российском сервере. Ретранслятор ничего не хранит: он принимает запросы Bot API **только с IP вашего российского сервера**, а вебхуки Telegram — только с секретным заголовком.

Порядок:
1. Купите зарубежный сервер, запишите его IP. На REG.RU добавьте запись **A: `tg` → IP зарубежного сервера** (получится `tg.kovagor.ru`).
2. **На российском сервере:** `bash scripts/set-relay.sh tg.kovagor.ru` — пропишет адрес ретранслятора в `.env` и покажет, какие значения понадобятся дальше. Затем `bash scripts/deploy.sh`.
3. **На зарубежном сервере:** подключитесь по SSH, скачайте репозиторий (как в `DEPLOY.md`, шаг 4), затем:
   ```bash
   cd kovagor
   sudo bash scripts/server-setup.sh
   bash relay/init.sh       # спросит: tg.kovagor.ru, IP российского сервера, домен сайта, секрет вебхука
   ```
   Проверка: `curl -sS https://tg.kovagor.ru/` должен ответить `ok`.
4. **На российском сервере:** `bash scripts/set-webhook.sh` — проверит бота и группу и подключит вебхук через ретранслятор.

Резервный канал на случай недоступности Telegram — заявки на email: `bash scripts/set-mail.sh` (см. ниже).

## Заявки на email (резервный канал)
Заявка уходит одновременно в Telegram и на email, и считается принятой, если дошла хотя бы по одному каналу. Если Telegram недоступен — вы получите письмо, а клиент увидит «заявка отправлена» (без кнопки перехода в бота).
Настройка: `bash scripts/set-mail.sh`, затем `bash scripts/deploy.sh`. Для Яндекс.Почты: сервер `smtp.yandex.ru`, порт `465`, в поле пароля — **пароль приложения** (id.yandex.ru → Безопасность → Пароли приложений → Почта).

## Важно
- **Нужен постоянный диск.** Связь «заявка ↔ тема ↔ клиент» хранится в `DATA_DIR/bot.sqlite` (в Docker это том `appdata`, он описан в `docker-compose.yml`). Делайте его резервную копию. Если файл потеряется, заявки не пропадут (они остаются в группе), но переписка в старых темах перестанет доставляться клиентам.
- **Vercel для переписки не подходит**: там нет постоянного диска. На Vercel заявки будут приходить простым сообщением в группу (нужны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_GROUP_ID`), без кнопки «Продолжить в Telegram». Полный режим — на VPS (`DEPLOY.md`).
- **Упрощённый режим** (без группы): задайте только `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — заявки придут в чат, переписки не будет.
- **Конфиденциальность.** Переписка и данные заявок хранятся в Telegram и в `bot.sqlite` на вашем сервере. Это нужно отразить в политике конфиденциальности (там есть пометка `TODO(legal)`); бот при первом обращении даёт клиенту ссылку на политику.
- **Безопасность.** Вебхук принимает запросы только с секретным заголовком; ссылка «Продолжить в Telegram» подписана, чужую заявку по номеру подобрать нельзя. Бот игнорирует любые чаты, кроме личных и вашей группы. Не публикуйте токен — если утёк, перевыпустите в @BotFather (`/revoke`) и обновите `.env`.
- **Лимиты.** Если один клиент шлёт больше 30 сообщений в минуту, лишние игнорируются (защита от спама, чтобы не создавать лавину тем).

## Если что-то не работает
| Симптом | Что проверить |
|---|---|
| Заявка пришла в общий чат группы, а не в тему | В группе не включены темы или у бота нет права «Управление темами» → `telegram-setup.mjs` покажет |
| Форма говорит «Не удалось отправить» | Неверный токен или id группы; `docker compose logs app` |
| Ответ менеджера не доходит клиенту | Клиент не нажал «Продолжить в Telegram» (бот предупредит в теме); либо заблокировал бота |
| Клиент пишет боту, а в группе тишина | Вебхук не подключён: `telegram-setup.mjs https://kovagor.ru`; `getWebhookInfo` покажет последнюю ошибку |
